Abstract

Smart-home assistants are expected to handle the diverse, realistic requests that arise in daily life. In such interactions, users often convey intent through cues beyond language—a pointing gesture, an ambient sound, or surrounding context. Existing smart-home benchmarks, however, are built largely around settings in which the user’s request is fully specified in text. To bridge this gap, we introduce OmniSmartHome, a multimodal smart-home benchmark in which users indicate the devices they intend to control through five types of multimodal cues: speech, gesture, sound, space, and user identity. OmniSmartHome contains 1,360 synthetic and 272 real-world episodes, each pairing visual observations with spatial audio. We evaluate 16 omnimodal large language models (Omni-LLMs) and reveal that, although they perform strongly when the target device is explicitly named in speech, performance drops substantially when resolving the target requires reasoning over implicit multimodal evidence. As a lightweight agent baseline, we provide PROME (PROcedural Memory for multimodal Evidence gathering), which equips agents with specialized audio-visual perception tools and procedural memory for deciding which evidence to gather and how to combine it. PROME consistently improves both device grounding and task execution across six Omni-LLMs.

Benchmark

OmniSmartHome defines an episode profile along three dimensions: a grounding type, indicating which modality carries the evidence needed to resolve the intended target device; a query type, indicating what the user asks for; and a feasibility type, indicating whether the request can be fulfilled or not. Every episode provides a visual observation of the room where the speaker is, a first-order Ambisonics recording of the spoken request together with the sounds of active devices, and the initial home state: rooms, devices, and household members.

Five grounding types

One explicit baseline (G0) and four implicit types (G1–G4) that rely on non-verbal cues.

G0 Speech The user explicitly names the target device in the spoken utterance, so grounding reduces to speech recognition alone.
G1 Gesture The user refers to the target device deictically (“Turn that off”) while pointing toward it, requiring the agent to interpret the gesture and ground it in the visual scene.
G2 Sound The user refers to the target device by the sound it emits (“Stop that humming noise”), requiring the agent to detect and localize the sound source and associate it with the corresponding device.
G3 Space The user refers to the target device using an egocentric direction (“Turn off the light on my left”), requiring the agent to reason about that direction from the user’s perspective and identify the target located there.
G4 User identity The user refers to the target device through a possessive reference (“Turn off the AC in my room”), requiring the agent to identify who is speaking and resolve the corresponding person-specific reference.

Simple agentic baseline

Before operating a device, an agent is required to first resolve which device the user refers to from audio-visual context. This involves actively gathering multimodal evidence and integrating it differently depending on how the request is grounded in the environment. To support this process, we introduce PROME (PROcedural Memory for multimodal Evidence gathering), a simple agent baseline. PROME equips the agent with a set of audio-visual perception tools and augments its reasoning with a procedural memory that guides when such tools should be invoked, in what order, and how their outputs should be combined.

Figure 4: Illustration of our agent framework. Components highlighted in orange are used only by PROME. The agent receives the visual and acoustic observation and reasons about the target device in a ReAct loop through simulator-interaction and perception tools. PROME additionally provides procedural guidance. Once the target device is identified, the agent declares it and either queries its information (Q1) or executes the requested operation (Q2–Q4) via simulator-interaction tools. Grounding accuracy evaluates the declared target device, while goal accuracy is evaluated from the simulator state or by an LLM judge.

Base agents. Small open-source models show generally low grounding accuracy across all grounding types, with MiniCPM-o-4.5 performing best in this group. Their goal accuracy is often substantially lower than their grounding accuracy, in some cases by more than a factor of two: even when these models identify the target device, they still struggle to complete the requested goal. Larger open-source models achieve higher overall accuracy with a smaller gap between grounding and goal performance. Their grounding is strongest on G0, where identifying the target device requires little beyond speech recognition, but drops on G1–G4, which require integrating additional non-verbal evidence. Proprietary models generally outperform open-source models, yet show a similar gap between G0 and G1–G4. For these stronger models, the contrast between nearly saturated grounding and goal performance on G0 and lower performance on G1–G4 highlights multimodal grounding as the primary challenge of the benchmark.

PROME. PROME improves overall grounding and goal accuracy across all six backbones. Notably, Gemma4, the weakest larger open-source baseline, gains 23.4 / 34.1 percentage points in grounding / goal accuracy, respectively, surpassing the other open-source base agents. PROME also improves the strong Gemini models by 4.5 / 6.1 points on Gemini-2.5-Flash and 4.0 / 6.1 points on Gemini-2.5-Pro. Across grounding types, as expected, gains are limited on G0 but larger on G1–G4.

Error analysis

We categorize common grounding failures for Qwen3-Omni-Think, Gemini-2.5-Flash, and Gemini-2.5-Pro, comparing the base agents with PROME.

Figure 5: Grounding failures by grounding type (base agents vs. PROME).

G1 Gesture. Among wrong-device errors, 45–59% select the candidate nearest to the user’s hand or body across models, suggesting that agents rely on proximity rather than the pointing direction.

G2 Sound. Base agents often declare the sound source prematurely, without checking the states of multiple candidate devices. Instead, they rely on semantic priors about which devices typically produce a given sound: an alarm originating from a refrigerator may be incorrectly attributed to a microwave simply because the agent assumes that microwaves commonly emit alarm sounds. PROME reduces such errors by guiding the agent to localize the sound source or inspect candidate device states.

G3 Space. Directional failures depend strongly on the user’s orientation. Over 70% of them occur when the speaker faces the camera, where the speaker’s left–right directions are reversed relative to the image. Errors are substantially less frequent when the speaker faces away from the camera. PROME resolves this ambiguity with multimodal tools such as head-pose estimation, reducing opposite-side declarations.

G4 User identity. Many identity failures occur when the agent declares a device without first identifying who is speaking. PROME substantially reduces these cases by prompting the agent to gather identity evidence before committing to a device.
